# TS-002: Suno lineage extraction and automation

**Run:** 2026-10-03, in the maintainer's signed-in browser, driven through Claude in Chrome. Existing cover clips were read from the library; the maintainer then created one clip set each by Reuse Prompt, Mashup, Sample, Extend, Use as Inspiration, and Voice, and moved one source clip to Trash. An in-page recorder captured Suno's requests and responses (no headers). Sanitized examples are in `extension/fixtures/suno/lineage-metadata.examples.json`.

## The lineage list

This is the list the roadmap claim "captures every lineage relationship and source identifier the provider exposes" is measured against. Every clip has `metadata.task`, `metadata.type`, and `metadata.is_remix`; a plain generation has `task: "agentic_thinking"` and no source fields.

The same seven rows are in `TS-002.lineage.json` beside this file, which the import's lineage coverage test reads (#137).

| Suno action | `metadata.task` | Source identifiers | Other markers | Distinguishable after generation? |
|---|---|---|---|---|
| Cover | `cover` | `metadata.cover_clip_id`, `metadata.edited_clip_id` | badge `COVER` | Yes |
| Mashup | `mashup_condition` | `metadata.mashup_clip_ids` (two IDs); `clip_roots.clips` (two) | badge `MASHUP` | Yes |
| Sample this song | `chop_sample_condition` | `clip_roots.clips` only; nothing in `metadata` | `is_remix: true` | Yes |
| Extend | `extend` | `metadata.edited_clip_id`; `metadata.history[]` (`id`, `continue_at`); `clip_roots.clips` | `continue_at`, `infill`, badge `EXTEND 1`, `is_remix: true` | Yes |
| Use as Inspiration | `playlist_condition` | `metadata.playlist_id`, `metadata.playlist_clip_ids` | none | Yes |
| Voice | `vox_playlist_condition` (seen combined with an Inspiration source) | `metadata.persona_id`; top-level `persona` object | `is_persona_root` | Yes |
| Reuse Prompt | none (no `task` at all) | **none** | none | **No.** Indistinguishable from a new custom-mode generation. |

**`clip_roots`** is a top-level field on a clip in the library feed: `{ clips: [{ id, title, image_url, is_public, user_display_name, user_handle, user_avatar_image_url }], clip_attribution_type: "remix" }`. It was present for Mashup, Sample, and Extend, and absent for Reuse Prompt, Inspiration, and Voice. It was not checked for Cover.

The PRD's seven actions map as follows: Cover, Mashup, Sample This Song, Use as Inspiration, and Voice exist under those names; **Reuse Prompt exists but leaves no lineage**; **"Remix" is the name of the menu, not an action**. Extend, which the PRD does not list, is the commonest edit and does leave lineage. Suno also offers Crop, Remove Section, Reverse, Speed, Fade In/Out, Add Vocal, Edit instruments/vocals, Replace Section, Get Stems/MIDI, Remaster, and Add stem; none was exercised.

## Findings by question

| Question from the PRD | Answer |
|---|---|
| Which provider fields and page state identify parents, playlists, and action types? | The table above. On the page, the action is chosen from the clip's **Remix** or **Edit** menu, or from a mode selector in the Create form's Audio section. |
| Source-count limits for Mashup and playlist-backed Inspiration? | **Mashup: exactly two songs.** With one loaded the form says "Add one more song to create a mashup" and Create is disabled; the maintainer confirmed a third cannot be added, and the resulting clip has two `mashup_clip_ids`. **Inspiration: up to four individual songs, or one playlist.** Started from a song's menu, it accepts up to four songs; started from the Create screen, it accepts only a playlist, which may hold any number of songs (maintainer's observation). This matches the PRD's two source modes. |
| Do the actions produce distinguishable lineage metadata? | Yes for Cover, Mashup, Sample, Extend, Inspiration, and Voice. **No for Reuse Prompt.** |
| How to verify the intended source is selected on the Create page before populating? | **Advanced mode:** an "Audio" section appears with the source's title, a player, and a mode selector showing the action (Cover, Mashup, Sample, Inspo, Extend, …). **Simple mode:** a chip above the prompt. In both, the source's thumbnail address contains the source clip's ID (`…/image_<clip id>.jpeg`), which is the check. A source applies only to the mode (Simple or Advanced) that was active when the action was chosen. Choosing Cover also pre-fills Lyrics from the source and hides the Inspo button. |
| Behaviour when a source is trashed, unavailable, not imported, in another workspace, or needs a plan the user lacks? | **Trash:** `POST /api/gen/trash`; a trashed clip leaves the library feed (no clip there had `is_trashed: true`) and appears in `GET /api/clips/trashed_v2` with `is_trashed: true`. So "in Suno Trash" is detected by reading the trashed list, and "Remote Missing" is a linked ID in neither list. **A derived clip keeps showing its source after the source is trashed:** the derived song's page still showed a "Cover of" panel naming the trashed source (maintainer's observation), so existing lineage stays readable. **Plan-gated actions** are labelled in the menus: Inspo and Voice are Pro; several edits are Pro; Add stem is Premier. The rest was not determined. |

## Other observations

- A derived song's page shows a panel naming its source (for example "Cover of" with the source's title and creator), which remains after the source is moved to Trash.

- In the Create response, an Inspiration source has `playlist_id: "inspiration"` (a literal); in the feed it has become a UUID. Suno builds a playlist behind the scenes.
- The Create form's `+ Audio`, `+ Voice`, and `+ Inspo` buttons are the same sources reached from the other direction.
- The library's own filters name Suno's clip kinds: Full Songs, Covers, Extensions, Voices, Remasters, Stems, and clips from Edit Mode.
- Clip-level actions available to the user are listed per clip in `action_config.actions` with `disabled` flags (see the TS-001 fixture).

## Decision

**Captured on import (all seven rows above):** n8Tracks reads `metadata.task`, the source-identifier fields in the table, and `clip_roots`, and records lineage for Cover, Mashup, Sample, Extend, Inspiration, and Voice. Unimported sources become "Not imported" external references keyed by Suno clip ID, using `clip_roots` titles where present. The raw JSON is always kept, so fields added later are not lost.

**Reuse Prompt cannot be captured from Suno.** It is recorded only when n8Tracks itself started the action, from n8Tracks' own Version source; an imported clip made by Reuse Prompt arrives as a plain generation.

**Automated from n8Tracks (extension opens the source and chooses the action):** Cover, Mashup, Sample, Extend, Inspiration, and Reuse Prompt, each verified on the Create form by the Audio section or chip and the source clip ID in its thumbnail address before any other field is populated. **Voice** is automated only if the persona can be selected reliably; otherwise it is a manual step with the form otherwise populated.

**System relationship types** in n8Tracks (M3 #92) should add **Extend** to the seven. "Remix" stays as a general type for imported clips whose `clip_roots.clip_attribution_type` is `remix` but whose task is unrecognised.

## Degraded and manual fallbacks

- If `metadata.task` holds a value n8Tracks does not know, the Generation is imported with its raw JSON, lineage is taken from `clip_roots` when present, and the relationship type is the general Remix type.
- If the Audio section or chip cannot be verified on the Create form, automation stops and names the step; the user can choose the source by hand and continue.
- If a required source is in Trash (found in the trashed list) or in neither list, automated generation for that Version is blocked with the source named, as the PRD requires.

## Not determined

- Whether there is an upper limit on the size of a playlist used as Inspiration.
- `clip_roots` on Cover clips, and whether `cover_clip_id` and `edited_clip_id` ever differ.
- What the feed's `clip_roots` and source-ID fields contain after a source is trashed (the song page still names the source), and what happens after a source is permanently deleted.
- Behaviour for a source in another workspace, a source that is not the user's own, and a plan-gated action on a plan without it.
- Lineage left by the edit actions that were not exercised (Crop, Remove Section, Reverse, Speed, Fades, Add Vocal, Replace Section, Stems, Remaster, Add stem).
- The request bodies sent for each action (not captured).
