# TS-006: Suno's model menu

**Run:** 2026-10-08, in the maintainer's signed-in browser, driven by the orchestrator, to capture the model menu that #146 and #147 listed as blocked on a capture (D9, #339; TS-005 did not capture it). Page HTML only (scripts and styles removed); no network recording. Nothing was chosen, created, published, deleted, or trashed; Create and "Create Custom Model" were never pressed. Raw captures stay in the ignored `docs/.notes/suno/ts-006/`. Fixtures: `extension/fixtures/suno/page.create-songs-model-menu.html` and `page.create-sounds-model-menu.html`, sanitized as TS-005's were (placeholder IDs from `…000000000301`; the snapshots hold none).

## The model button

- The page has **one** model button (`aria-haspopup="menu"`, its text the chosen model, "v6"), at the top of the form. The Songs and Sounds tabs share it, and the menu it opens.
- It sits three elements out from the "Create form mode" tab list and from the "Credits remaining" button, so the adapter's existing targets (`MODEL_BUTTON` around the mode tabs, `SOUNDS_MODEL_BUTTON` around the credits, both `levels: 3`) find it on both snapshots. They were not changed. On the Sounds tab there is no mode tab list, so only `SOUNDS_MODEL_BUTTON` finds it there.
- While the menu is open the button has `aria-expanded="true"`.

## The model menu

- `role="menu"`, no `aria-label`, `aria-labelledby` the button: its name is the model the button shows ("v6").
- Its items, in order:
  1. **Create Custom Model** (Beta), "Create a model based on your uploads (100 Credits)": a `menuitem`. It spends credits and is never pressed. Its name starts with Create, so the forbidden-control matcher refuses it.
  2. **v6** (Pro), "Powerful. Versatile. Refined. Our best model yet.": `menuitemradio`, `aria-checked="true"`.
  3. **v6-wild** (Pro), "Best for experimental ideas.": `menuitemradio`, `aria-checked="false"`.
  4. **v6-mini**, "A free, more efficient version of premium v6 models.": `menuitemradio`, `aria-checked="false"`.
- Each item's text runs the label into its badge and description ("v6ProPowerful…"). The label is its own element (the first `.truncate` span), so the accessible name reads "v6 Pro Powerful. …": the label is the name's first word.

## Not captured

- The menu after a choice: whether it closes, and what the button then shows. The adapter reads the model back from the button's text and closes the menu with the button if it is still open.
- A model shown disabled for the user's plan, and any model other than these three (older models such as v4.5 are not offered).

## Decisions

- **TS-006-1. A model is the `menuitemradio` whose name's first word is the model** ("v6" never matches "v6-wild Pro …"), compared without regard to case, inside the menu labelled by the button. Only `menuitemradio` is looked for, so "Create Custom Model" cannot match.
- **TS-006-2. The read-back is the button's text.** An item already checked is not pressed again; a model the button already shows needs nothing pressed at all.
- **TS-006-3. A model outside v6, v6-wild, and v6-mini is failed without opening the menu**, as a Variety or Key Suno does not offer is: the extension never guesses a model. A listed model the menu does not show is `unavailable`, and the menu is closed.
